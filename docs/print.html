Terrarium

Introduction

Terrarium is a simple, extensible 3D engine for Rust. It stands on two foundations:

  • wgpu for 3D graphics.
  • eframe for 2D graphics.

Motivation

Building a 3D application in Rust usually starts with an integration project.

Before the first triangle appears you have chosen a windowing layer, an event loop, a renderer, a way to draw interface on top of it, and an asset pipeline, and then wired them together.

Each choice is reasonable on its own, but the wiring is repeated by every app and rarely resembles the interesting part of the work.

Features

Terrarium hands you what you need so you can focus on the game, not the machine:

  • Batteries included. Terrarium is your audio, lighting, physics, windowing, shading, scene graph and persistence.

  • Native and web, one code branch. All Terrarium systems are carefully designed to work anywhere.

  • Deterministic enough to test. Run the full update and render path headlessly. Don’t let the complexity of your application get in the way of testing it.

  • Interoperable by default. The API is built in layers and meant to give you the flexibility to integrate with other ecosystems.

Quick start

This guide assumes you are starting from scratch.

1. Install Rust

Terrarium is built in Rust. You can install Rust with any of those options:

  • rustup.
  • mise (mise use -g rust).
  • Docker.

Verify that Rust is correctly installed:

rustc --version
cargo --version

2. Install Terrarium

Create a Rust project:

cargo new awesome_game
cd awesome_game

Terrarium is directly accessible from crates.io. Add it as a dependency:

cargo add terrarium

On Debian/Ubuntu, install native build dependencies if they are not already present:

sudo apt update
sudo apt install build-essential pkg-config libasound2-dev libjack-jackd2-dev libudev-dev

3. Create your first scene

Replace src/main.rs with:

use terrarium::*;

fn main() {
    Terrarium::new()
        .run(|engine| {
            engine.workspace_mut().add_child(Part::new());
            Ok::<(), AppCreationError>(())
        })
        .unwrap();
}

Run the app:

cargo run

Instance composition

The instance! macro builds instance APIs from named fields and inherent methods. It can extend an existing instance, combine independent capabilities, and expose stored or computed properties to the devtools inspector.

use terrarium::*;

instance!({
    /// A primitive with a spring.
    #[derive(Clone, Debug)]
    pub struct SpringPart {
        #[extends]
        part: Part,
        /// Spring stiffness in newtons per meter.
        #[property(default = 20.0)]
        stiffness: f32,
    }
});

fn main() {
    let spring_part = SpringPart::default().with_stiffness(30.0);
}

This definition inherits Part’s instance identity and APIs. It also generates the stiffness, set_stiffness, and with_stiffness methods. The sections below describe the field roles and generation rules in detail.

Composition fields

instance! requires a concrete struct with named fields. Generic instance types and conditional composition fields are not supported. Annotate fields with one composition role:

AttributeRole
#[extends]Inherits an instance identity and the composed type’s APIs. An instance can have at most one extends field.
#[compose]Adds a capability without adding another instance identity. A type can compose multiple capabilities.
#[data]Provides InstanceData for a new instance type that does not extend another instance.

An instance has at most one identity provider: either an #[extends] field or an #[data] field. A type with only #[compose] fields can define a capability without an instance identity.

use terrarium::*;

instance!({
    #[derive(Clone, Debug)]
    pub struct Motor {
        #[property(default = 2.0)]
        speed: f32,
    }
});

instance!({
    #[derive(Clone, Debug)]
    pub struct MotorPart {
        #[extends]
        part: Part,
        #[compose]
        motor: Motor,
    }
});

instance!({
    #[derive(Clone, Debug)]
    pub struct Group {
        #[data]
        data: InstanceData,
        #[property(default = String::new(), borrow, into)]
        label: String,
    }
});

fn main() {
    let motor = Motor::default().with_speed(0.0);
    let motor_part = MotorPart::default()
        .with_transparency(0.5)
        .with_speed(0.0);
    let group = Group::default().with_label("My Group");
}

Motor is a capability, while MotorPart has the identity and instance APIs of Part as well as the APIs provided by Motor. Group declares its own identity storage with InstanceData.

Field properties and defaults

Mark a stored field with #[property] to generate a getter named after the field, a set_<field> setter, and a consuming with_<field> builder. The property attribute accepts these options:

OptionEffect
default = expressionUses the expression to initialize the field. Without an explicit initializer, fields use Default::default().
sanitize = expressionCalls the expression as a function on values passed to the setter.
borrowReturns &T from the getter and generates <field>_mut(&mut self) -> &mut T.
intoMakes the builder accept impl Into<T> and convert its argument. The setter still accepts T.

For example:

#[property(default = String::new(), borrow, into)]
label: String,

#[property(default = 0.0, sanitize = sanitize_transparency)]
transparency: f32,

Overrides

Replace a method inherited from a composed API by annotating a method in the type’s inherent impl with #[r#override(Type::method)]. The replacement must keep the inherited method’s name and use a borrowed receiver with concrete arguments. Its signature must match the inherited method.

use terrarium::*;

instance!({
    #[derive(Clone, Debug)]
    pub struct PlanarPart {
        #[extends]
        part: Part,
    }

    impl PlanarPart {
        #[r#override(PVInstance::set_pivot)]
        pub fn set_pivot(&mut self, mut pivot: glam::Mat4) {
            pivot.w_axis.y = 0.0;
            self.pv_instance_mut().set_pivot(pivot);
        }
    }
});

fn main() {
    let planar_part = PlanarPart::default()
        .with_transparency(0.5)
        .set_pivot(glam::Mat4::IDENTITY);
}

The override is dispatched through the inherited API, including when that API is accessed through a composed view. Further composed types inherit the override unless they replace the same method themselves.

Inspector properties

With devtools enabled, the macro generates inspector support unless #[instance(inspect = false)] is set. Instance identity fields such as the name and attributes are included along with annotated properties from the type and its composed APIs.

An inherent getter can also be marked #[property] to expose a computed property. The inspector applies edits through the matching set_<getter> method. Add options to control how it is presented or validated:

OptionEffect
flattenExposes the property’s nested inspector fields without prefixing their paths with the getter name.
validate = methodCalls the named method with the proposed property value. The edit is rejected if it returns false.
 
use terrarium::*;

instance!({
    #[derive(Clone, Debug)]
    pub struct TransformData {
        #[data]
        data: InstanceData,
        #[default(glam::Mat4::IDENTITY)]
        pivot: glam::Mat4,
    }

    impl TransformData {
        #[property(flatten, validate = accepts_pivot)]
        pub fn transform(&self) -> glam::Mat4 {
            self.pivot
        }

        pub fn set_transform(&mut self, transform: glam::Mat4) {
            self.pivot = transform;
        }

        pub fn accepts_pivot(&self, pivot: glam::Mat4) -> bool {
            pivot.is_finite()
        }
    }
});

fn main() {
    let accepts_pivot = TransformData::default().accepts_pivot(glam::Mat4::IDENTITY);
}

Without flatten, nested property paths are prefixed by the getter name. For example, a nested field under transform is edited at transform.position. With flatten, its path is position. Use inspect = false when providing a separate inspector implementation.

Nested definitions

Definitions can be nested in Rust modules and can extend other custom definitions. When a type is declared in a module, set #[instance(path = crate::module)] to that crate-rooted module path. The default is crate.

use terrarium::*;

mod models {
    use super::*;

    instance!({
        #[instance(path = crate::models)]
        #[derive(Clone, Debug)]
        pub struct SpringPart {
            #[extends]
            part: Part,
            #[property(default = 20.0)]
            stiffness: f32,
        }
    });
}

instance!({
    #[derive(Clone, Debug)]
    pub struct WeightedSpring {
        #[extends]
        spring: models::SpringPart,
        #[property(default = 2.0)]
        mass: f32,
    }
});

fn main() {
    let spring = WeightedSpring::default().with_mass(1.0);
}
